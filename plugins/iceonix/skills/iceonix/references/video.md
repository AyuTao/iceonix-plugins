# 做视频

冰爪 App 内置视频模板，`render_video` 用系统自带的网页组件逐帧渲染，用户不用装任何工具。你负责写文案、挑素材、写分镜和按反馈修改；冰爪负责节拍分析、配音、字幕、混音和出片。适合产品宣传、热点资讯、知识讲解，横屏或竖屏。

有真人口播或录屏素材要剪时不用本章，按[剪辑与达芬奇](editing.md)做。

## 流程

1. **对齐需求**：主题、时长（15～90 秒）、画幅（横屏 1920×1080 或竖屏 1080×1920）、类型、风格和结尾信息。
2. **写旁白稿**：6～10 句，每句一个意思、不超过 25 字，用口语。**先给用户确认文案**再往下做。热点资讯必须基于用户给的来源，不编造数字和引语（写法见下文「热点和推文做成视频」）。
3. **建工作目录**：`<冰爪工作区>/Videos/<英文短名>/`，工作区默认 `~/Movies/Iceonix`（`list_projects` 返回的项目都在 `<工作区>/Projects/` 下，可据此推断）。音乐、素材、旁白都放进这个目录，分镜里用相对路径。
4. **音乐**：用用户提供的文件；没有就请用户提供，或用 `generate_music(prompt, outputPath)` 生成（用用户自己的 Gemini Key；免费层会提示要开通付费，这时请用户提供音乐）。提示词写清结构，例如「安静前奏约 8 秒，第 8 秒鼓点进入，中段有力，最后 8 秒收尾」，分镜才好卡点。提醒用户留意音乐的商用授权。
5. **分析节拍**：`analyze_music(audioPath)`，拿到 `drops`（鼓点）和 `sections`（安静段、高能段）。
6. **素材**：用户给的截图或图片、项目素材，或 `generate_image` 生成的图，复制到 `assets/`。截图里有聊天、通讯录、账号等隐私信息时提醒用户确认。没有合适素材的场景用纯文字场景（`question`、`words`），不要硬塞图。
7. **配音**：`synthesize_speech` 每句一个文件，存到 `vo/l1.wav`、`vo/l2.wav`……
   - 第一句用 `instruct` 设计音色，或用用户的 `voiceId`。其余句子**必须用同一音色**：传同一个 `voiceId`，或把第一句的文件作为 `cloneRefPath`、第一句文字作为 `cloneRefText`（参考音只取前 5 秒，第一句尽量短）。不要每句都用 `instruct` 重新设计。
   - **逐句回听**：`transcribe_video(videoPath=vo/l1.wav, referenceText=这句文案)`，把 `data.asr` 和文案逐字对照：英文缩写读错（如 LOG）、近音字读错（如「双摄」读成「双色」）、句尾被截掉。有错就改写文字（如 LOG 写成 Log）重配这一句，通过后再往下。
   - 结果顶层的 `words` 是每个字相对文件开头的时间。配音文件开头常有 0.2～1.3 秒静音，**分镜里关键词、打勾的时刻 = 这句的 `at` + 对应字的 `start`**，不要按文件开头估。各句音量不用管，混音时统一。
8. **写分镜** `storyboard.json`（格式见下），放在工作目录根下。
9. **预览**：`render_video(storyboardPath, outputPath=<工作目录>/out/preview.mp4, quality=preview)`，耗时约等于片长。没完成时用 `get_video_render(renderId)` 继续等。先修掉 `warnings` 里的旁白重叠、超出片尾等问题。
10. **按对话修改**：用户说「18 秒那个标题改成…」「第二段太快」，改分镜后重新出预览（常见修改见下表）。
11. **出正片**：用户确认后用 `quality=final`（1 分钟 30fps 约 2 分钟，60fps 约 4 分钟）。一次只能渲染一个视频，预览满意前不要出正片。
12. **归档与发布**：放进冰爪项目时，`add_project_asset` 加入成片，再 `create_project_work(kind=video, assetIds=[…])`。发布按[发布与登录](publish.md)做，真实发布前让用户确认标题、正文、标签、封面和平台。

## 分镜格式

```json
{
  "title": "新功能介绍",
  "size": [1080, 1920],
  "fps": 30,
  "duration": 32,
  "brand": { "name": "品牌名", "latin": "BRAND", "icon": "assets/logo.png" },
  "theme": { "accent": "#7fdcff" },
  "music": { "file": "music/track.m4a", "voiceOverMusicDb": 12, "fadeOut": 2.4 },
  "captions": {},
  "voice": { "lines": [
    { "id": "l1", "at": 1.2, "text": "一个人，能不能撑起一整个内容团队？" },
    { "id": "l2", "at": 9.4, "text": "一键录屏，镜头自动追焦。" }
  ] },
  "scenes": [
    { "type": "question", "from": 0, "to": 7.6, "kicker": "一个人，", "title": "能不能撑起一整个内容团队？", "at": 1.2 },
    { "type": "logo", "from": 7, "to": 9.3, "at": 8.04 },
    { "type": "feature", "from": 9.2, "to": 14, "kicker": "01", "title": "一键录屏", "sub": "镜头自动追焦", "shots": ["assets/editor.png"] },
    { "type": "outro", "from": 26, "to": 32, "tagline": "一句品牌标语", "info": "@你的账号" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `size` / `fps` / `duration` | 画幅、帧率（15～60，常用 30）、总时长（秒，通常等于音乐长度） |
| `brand` | 品牌名、英文名、logo（方形图）；`iconStyle`：`app`（默认，圆角方形图标）或 `glow`（深色底发光图形，裁成圆形柔光） |
| `theme` | `accent` 强调色（小标题、字幕当前字）；`background` 背景光晕色、`glow` 粒子与冲击波颜色，按品牌色调整 |
| `music` | 音乐文件；`voiceOverMusicDb` 旁白期间音乐比人声低多少（默认 12）；`fadeOut` 结尾淡出秒数 |
| `captions` | 有这个字段就按旁白逐字出字幕；`{"position": "top"}` 放顶部；`{"hideDuring": [...]}` 指定不显示字幕的场景类型（默认 question、words、logo、outro 不显示） |
| `voice.lines` | 每句 `id`、开始秒数 `at`、文字 `text`；音频默认读 `vo/<id>.wav`，也可用 `audio` 指定 |

**场景类型**（都有 `from`、`to`，单位秒，相邻场景可重叠 0.1～0.5 秒做交叉）：

| type | 用途 | 关键字段 |
|---|---|---|
| `question` | 开场问句，逐字浮现 | `kicker` `title` `at` |
| `words` | 关键词逐个弹出，随后上移并升起一张图 | `words` `times` `sub` `subAt` `shot` `shotAt` `textOut` |
| `logo` | 闪白、logo 炸开，放在鼓点 | `at`（填鼓点时间）；`claws: true` 时鼓点前先划三道光痕 |
| `feature` | 左文右图（竖屏为上文下图），可带一次推近 | `kicker` `title` `sub` `shots`（1～2 张） `zoom{at,out,label}` |
| `chat` | AI 对话：打字、回复、弹出面板、周围标签 | `prompt` `reply` `replyDone` `typeAt` `replyAt` `panel` `panelAt` `chips` |
| `checklist` | 逐项打勾，再弹出结果图 | `items[[名称, 颜色]]` `times` `panel` `panelAt` |
| `wall` | 倾斜的图片墙、标题和关键词快闪 | `shots` `icon:"lock"` `title` `sub` `recap` `recapTimes` `textEnd` |
| `outro` | 粒子汇聚成 logo，品牌名、标语、信息行 | `tagline` `info`（`from` 是 logo 出现的时刻） |

## 卡点与节奏

- `logo` 的 `at` 填 `drops[0]`，鼓点那一下闪白炸开（开了 `claws` 时光痕从鼓点前约 1.1 秒开始）。
- 音乐在每句旁白开口前约 0.45 秒压下去：鼓点后至少隔 1 秒再开口，鼓点才响得出来。
- `words` 场景的第一个词尽量在场景开始后 1 秒内出现；旁白的铺垫语可以单独做一个 `words` 场景，或让上一个场景多停一会儿。
- 截图可以是桌面横图或手机竖图，模板会自动收放；竖屏里 `feature` 放两张手机截图时并排显示。
- 安静段放开场问句和铺垫，高能段放功能展示，最后一个安静段放 `outro`。场景切换、关键词弹出、清单打勾尽量对齐拍点。
- 每句旁白的 `at` 之间留够这句的时长，`render_video` 的 `warnings` 会提示重叠。
- 竖屏底部约 15% 会被平台界面挡住，字幕默认已避开，不要把重要文字放在最底部。

## 常见修改

| 用户说 | 改什么 |
|---|---|
| 「这段太快 / 太慢」 | 该场景的 `from` / `to` 和场景内动作时间；旁白 `at` 跟着挪 |
| 「标题改成…」 | 对应场景的 `title` / `kicker` / `sub` |
| 「换一张图」 | 场景的 `shot` / `shots` / `panel` |
| 「旁白改成…」 | 改 `text` 后重新合成那一句，检查时长是否还放得下 |
| 「音乐太大 / 太小」 | `music.voiceOverMusicDb`，越大音乐越小 |
| 「某句读错了」 | 改写文字（缩写、多音字换写法）后重新合成，再回听 |
| 「换个颜色」 | `theme.accent` |
| 「字幕挡住了」 | `captions.position` 改成 `top`，或在 `hideDuring` 里加该场景类型 |
| 「改成竖屏」 | `size` 改为 `[1080, 1920]`，重新预览检查 |

## 热点和推文做成视频

用户给推文链接、截图或资讯，要做成短视频时：

1. **只用来源里的事实**：自己读链接和截图，提取核心事件、相关人物或机构、官方说法、正反观点和提醒。来源没说的数字和引语不要写。
2. **旁白五段节奏**（约 60～75 秒）：
   - 开头钩子（0～8 秒）：最反常、最影响观众的那件事。
   - 起因（8～20 秒）：为什么会这样。
   - 官方说法（20～45 秒）：权威回应、边界在哪里，可配推文或公告截图。
   - 不同观点（45～58 秒）：双方各自的理由。
   - 怎么办（58～72 秒）：观众该怎么自查、怎么做。
3. **发布文案像人写的**：第一人称或从业者视角，段落间空行；不要堆砌 💥📌🔍⚠️ 这类 Emoji，也不要无意义的项目符号。
4. **标题和标签**：视频号标题上限 16 字，列表页 12～14 字最不容易被截断；标签 4 个左右，精准即可。
5. 画面按上面的分镜格式做（截图放 `feature` 或 `wall`），出片后按[发布与登录](publish.md)批量发布。

## 注意

- 画面里并非真实发生的数据（例如演示用的「全部发布成功」）要在交付时告诉用户是示意。
- 不要自动发布，发布和真实操作都要先得到用户确认。
